`NepaliDateFormat` formats a `NepaliDateTime`, or any `DateTime`, as text in the Bikram Sambat calendar. It works like `DateFormat` from `package:intl`:

- the same **pattern letters** (`yyyy-MM-dd`, `EEE, MMM d`)
- the same **skeleton constructors** (`NepaliDateFormat.yMMMd()`) and constants (`NepaliDateFormat.YEAR_MONTH_DAY`)
- the same `addPattern` / `add_*` composition

Skeletons are laid out like intl's `en` locale in English and its `ne` locale in Nepali. Nepali output uses Devanagari digits.

```dart
final date = NepaliDateTime.parse('2072-06-03T17:00:00');

NepaliDateFormat.MEd().format(date);             // Sun, 6/3
NepaliDateFormat.MMMMEEEEd().format(date);       // Sunday, Ashwin 3
NepaliDateFormat.jms().format(date);             // 5:00:00 PM
NepaliDateFormat.yMd().add_jm().format(date);    // 6/3/2072 5:00 PM
NepaliDateFormat.yMd(.nepali).add_jm().format(date); // २०७२-०६-०३ १७:००
```

## Creating a formatter

```dart
NepaliDateFormat([String? pattern, Language? language])
```

- `pattern` is either a **skeleton name** such as `'yMMMd'`, which is resolved to the layout for the language, or an **explicit pattern** such as `'MMMM d, y'`.
- Without a pattern, the format is `yMMMMd jms`:

  ```dart
  NepaliDateFormat().format(date);              // Ashwin 3, 2072 5:00:00 PM
  NepaliDateFormat(null, .nepali).format(date); // २०७२ आश्विन ३ १७:००:००
  ```

- `language` defaults to [`NepaliUtils.currentLanguage`](/getting-started/language/) at the moment you create the formatter.

The resolved pattern is available as `pattern`:

```dart
NepaliDateFormat.yMd().pattern;          // M/d/y
NepaliDateFormat.yMd(.nepali).pattern;   // y-MM-dd
NepaliDateFormat().pattern;              // MMMM d, y h:mm:ss a
```

`format` accepts any `DateTime`. A plain `DateTime` is converted with `toNepaliDateTime()` first, which **keeps its time zone**:

```dart
NepaliDateFormat.yMMMMd().format(DateTime(2019, 8, 3)); // Shrawan 18, 2076
```

`parseAndFormat(string)` parses a BS date string with `NepaliDateTime.parse`, then formats it:

```dart
NepaliDateFormat.yMMMMEEEEd().parseAndFormat('2080-01-01'); // Friday, Baishakh 1, 2080
```

## Skeletons

Each skeleton is a named constructor and a constant. For example, `NepaliDateFormat.yMMMd()` is the same as `NepaliDateFormat(NepaliDateFormat.YEAR_ABBR_MONTH_DAY)` and `NepaliDateFormat('yMMMd')`.

<Aside type="note" title="Narrow no-break space before AM/PM">
  Like intl, the English `j…` skeletons put a **narrow no-break space** (` `) before AM/PM, not a normal space: `9:04 PM`. It looks the same on screen, but string comparisons in tests must use ` `. Explicit patterns such as `'h:mm a'` use whatever character you write.
</Aside>

The `j` skeletons use the clock that is usual for the language: 12-hour with AM/PM in English, and 24-hour in Nepali.

In Nepali, `a` gives the time of day instead of AM/PM:

```dart
for (final hour in [5, 12, 14, 18, 21]) {
  NepaliDateFormat('h a', .nepali).format(NepaliDateTime(2080, 1, 1, hour));
}
// ५ बिहान, १२ मध्यान्न, २ दिउसो, ६ साँझ, ९ बेलुकी
```

The time-zone letters show the zone of the value: `NPT` for Nepal Time, `UTC` for UTC, and the device's zone name for local values. (intl leaves them empty.)

```dart
NepaliDateFormat('HH:mm z').format(NepaliDateTime.nepal(2080, 1, 1, 9)); // 09:00 NPT
NepaliDateFormat('HH:mm Z').format(NepaliDateTime.utc(2080, 1, 1, 9));   // 09:00 +0000
```

### Examples

```dart
final date = NepaliDateTime.parse('2072-06-03T17:00:00');

NepaliDateFormat("yyyy.MM.dd G 'at' HH:mm:ss").format(date); // 2072.06.03 BS at 17:00:00
NepaliDateFormat("EEE, MMM d, ''yy").format(date);           // Sun, Ash 3, '72
NepaliDateFormat('h:mm a').format(date);                     // 5:00 PM
NepaliDateFormat("hh 'o''clock' a").format(date);            // 05 o'clock PM
NepaliDateFormat('yyyy.MMMM.dd GGGG hh:mm a').format(date);
// 2072.Ashwin.03 Bikram Sambat 05:00 PM
NepaliDateFormat('yyyy.MMMM.dd GGGG hh:mm a', .nepali).format(date);
// २०७२.आश्विन.०३ बिक्रम संबत ०५:०० साँझ
```

<Aside type="caution" title="A pattern that is also a skeleton name is resolved as a skeleton">
  The constructor checks skeleton names first. `NepaliDateFormat('H')` is the `H` **skeleton**, whose pattern is `HH`, so it prints `00` at midnight. `'H:mm'` isn't a skeleton name, so it prints `0:05`. The same goes for `'d'`, `'M'`, `'MMM'` (pattern `LLL`), `'y'`, `'m'` and `'s'`. Usually the result is the same. If you need the bare letter, add a literal to the pattern.
</Aside>

## Combining formats

`addPattern(pattern, [separator = ' '])` returns a **new** formatter: this formatter's pattern, then the separator, then `pattern`. A skeleton name passed to it is resolved, as in the constructor. The `add_*()` methods add the skeleton they're named after:

```dart
NepaliDateFormat.yMd().add_jm().format(date);                      // 6/3/2072 5:00 PM
NepaliDateFormat.yMMMd().addPattern('Hm', ' · ').format(date);     // Ash 3, 2072 · 17:00
NepaliDateFormat.yMMMMd().addPattern("'at' h:mm a").format(date);  // Ashwin 3, 2072 at 5:00 PM
```

<Aside type="caution" title="Formatters are immutable">
  In `package:intl`, `addPattern` changes the formatter. Here it **returns a new one** and the original doesn't change:

  ```dart
  final f = NepaliDateFormat.yMd();
  final f2 = f.add_jm();
  f.pattern;  // M/d/y
  f2.pattern; // M/d/y h:mm a
  ```

  Calling `f.add_jm();` without using the result does nothing.
</Aside>

## Time zones when formatting

The formatter prints the fields **in the value's own time zone**. To format an instant as Nepal Time, convert it first:

```dart
final instant = DateTime.utc(2024, 1, 1);

NepaliDateFormat('yyyy-MM-dd HH:mm').format(instant);
// 2080-09-16 00:00 (UTC fields)
NepaliDateFormat('yyyy-MM-dd HH:mm').format(instant.toNepaliDateTime().toNepalTime());
// 2080-09-16 05:45
```
